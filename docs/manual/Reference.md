# Reference

This page gathers the stable terms used across OpenOnyx.


## Why it exists

Shared language makes a vault easier to reason about. These terms describe the files and surfaces you encounter in the app.

## When to use it

Use the reference when a page uses an unfamiliar term or when you are configuring a workflow for someone else.

## Workflow

Encounter a term → confirm its file-first meaning → return to the feature page → apply it to a real note or vault decision.

## Terms

| Term | Meaning |
| --- | --- |
| Vault | A folder OpenOnyx reads and writes |
| Note | Usually a Markdown `.md` file |
| Space | An indexed collection for cited retrieval |
| Knowledge Graph | Explicit links between notes |
| AI Graph | Suggested semantic relationships |
| Canvas | A portable `.canvas` board |

> **OpenOnyx tip**
> Keep the distinction between links and AI suggestions clear: links are your decisions; suggestions are prompts to inspect.

> **OpenOnyx common mistake**
> Names can be customized in a vault. The file formats remain the portable reference.
