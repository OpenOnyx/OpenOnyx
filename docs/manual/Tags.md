# Tags

Tags are lightweight labels for status, topic, workflow stage, or review state. They are best for cross-cutting categories that do not belong to one folder.

## Add a tag

Write a hash symbol followed by the tag name:

```md
#research
#project/openonyx
#status/waiting
```

Nested tags use slashes. They help when a tag family has several states.

## Tags versus links

Use a tag for a broad state shared by many notes. Use a link for a meaningful relationship to a specific note.

| Use | Better tool |
| --- | --- |
| All notes waiting for review | Tag |
| A note depends on a decision | Link |
| Draft notes from interviews | Tag |
| A concept explains another concept | Link |

## Tag hygiene

Tags are easy to create and hard to clean up. Keep names boring and consistent. Prefer `#status/draft` over several variants like `#draft`, `#todo`, and `#needs-work` unless each means something distinct.
